# 流火（LiuHuo）配表工具 · 设计文档

> 版本 0.1 · 本文档描述整体架构与 P1（符号表 + 增量编译）的落地设计。
> 核心库 `LiuHuoCore`（Rust）+ 桌面应用 `LiuHuo`（Tauri 2 / Vite / React）。

---

## 1. 设计哲学

Luban 的哲学（Schema 定义 → 三阶段编译 → 数据加载 → 校验 → 导出）在 LiuHuo 中独立重实现，不照抄：

| 维度 | Luban（C#） | LiuHuo（Rust） |
|---|---|---|
| 定义文件 | XML | JSON（每个定义一个文件） |
| 类型系统 | 类继承 + 反射 | `enum TypeKind` + trait 注册表 |
| 扩展点 | `[SchemaLoader]` 反射特性 | trait + Registry + `register()` |
| 编译 | 每次全量三阶段 | **符号表 + 依赖图增量编译**（本设计的核心超越点） |
| 数据值 | DInt/DBean 类层次 | `DataValue` 枚举 |

---

## 2. 架构总览

```
                    ┌────────────────────────────────────────────┐
  磁盘 schema 文件  │  符号表 SymbolTable（内存单一事实源）         │
  schemas/{enums,   │   raws: HashMap<FullName, RawDef>           │
   beans,records,   │   defs: HashMap<FullName, DefValue>  编译缓存│
   tables}/*.json   │   diagnostics: HashMap<FullName, [Diagnostic]│
                    │   deps / reverse_deps: 依赖图               │
                    └────────────────────────────────────────────┘
                              │  register / update / remove / validate_draft
                              ▼
                    增量编译（只重检失效集合）· 三阶段：PreCompile → Compile → PostCompile
```

**两个驱动，共享核心**：
- **CLI（线性 DDP）**：`compile_all(raws)` → 全量注册 + 全量重检 + 导出。
- **GUI（增量）**：`register`（创建）/ `update`（编辑）/ `remove`（删除）/ `validate_draft`（未保存草稿校验），每次都只重编译受影响的最小集合。

## 3. 类型系统

`TypeKind`（纯类型）+ `TypeInfo`（类型 + 元信息 `nullable` / `tags`）。

- 基础：`bool i8..u64 f32 f64 string text datetime`
- 别名：`int→i32 long→i64 short→i16 byte/uint8→u8 float→f32 double→f64 time→datetime`
- 容器：`list<T> set<T> array<T> map<K,V>`（嵌套、空格）
- 可空后缀 `?`；标签后缀 `T(k=v,k2=v2)`（如 `int(range=[1,100])`）
- 引用：`Enum(full_name)` / `Bean(full_name)` / **`Unresolved(full_name)`**

> `Unresolved` 是增量编译的关键：类型串**语法合法即解析成功**，"引用了不存在的类型"是**语义错误**（依赖缺失），在编译阶段产生诊断，而不是让解析器报错。这样"创建新 Bean 引用尚未存在的 Enum"能立即诊断，且当 Enum 后来被创建时，依赖图反向失效会自动重检该 Bean 并消除诊断。

## 4. 符号表 + 增量编译（P1 核心）

### 4.1 数据结构

```rust
pub struct SymbolTable {
    raws: HashMap<String, RawDef>,      // 原始定义（唯一事实源）
    defs: HashMap<String, DefValue>,    // 编译缓存（Enum/Bean/Table/Record）
    diagnostics: HashMap<String, Vec<Diagnostic>>,
    deps: HashMap<String, Vec<String>>,           // full_name -> 它引用的 full_name
    reverse_deps: HashMap<String, HashSet<String>>, // 被引用 -> 引用者（失效传播）
}
```

### 4.2 依赖图

依赖边来源：
- `Bean.parent` → 父 Bean
- `Bean.fields[].type` → 引用的 Enum/Bean（含 `Unresolved`）
- `Table.value_type` → 引用的 Bean

`register` / `update` 时重建该定义的出边；`remove` 时删除。变更传播用 **BFS 沿 `reverse_deps` 反向重检**（传递失效，保证 A→B→C 链路正确）。

### 4.3 五个核心操作

| 操作 | 语义 | 副作用 |
|---|---|---|
| `register(def)` | 创建即编译 | 查重 → 编译 → 插入 → 建依赖边 |
| `update(def)` | 编辑即重编译 | 重编译 → 重建依赖边 → **反向重检所有依赖者** |
| `remove(name)` | 删除即失效 | 移除 → **依赖者重检（立即产生"未解析类型"诊断）** |
| `validate_draft(def)` | 校验未保存草稿 | 只读，不落盘、不污染符号表 |
| `compile_all(raws)` | CLI 全量 | 清空 → 注册全部 → 全量重检（两阶段） |

### 4.4 "创建即校验"链路（对应需求难点 3）

1. `create_definition_file` 落盘
2. `register(RawBean)` → O(1) 插入符号表
3. 单定义三阶段编译：字段类型串解析 → 引用不存在的类型 → **立即诊断"未解析类型 X"**
4. 依赖它的 Bean/Table 入失效队列异步重检
5. 前端实时拿到诊断，标红

**"动态向编译后的 Schema 添加类型变量"** = 符号表是可变索引，编译产物只是缓存，可随时失效重算——不存在"冻结"。

## 4.5 表值类型 = Record 独占；句柄（Handle）模型

**Table 的 value_type 只能是 Record**。Record 与 Bean 的字段语义分层：

| 维度 | Bean 字段 | Record 字段 |
|---|---|---|
| 字段名 | ✅ | ✅ |
| 字段类型 | ✅ | ✅ |
| 组 groups | ✅ | ✅ |
| 注释 comment | ✅ | ✅ |
| **句柄 handles** | ❌ 禁止（编译报错） | ✅ 一等属性，支持多个 |

句柄 = "如何对该字段数据进行处理"的声明，为数据校验服务（range 范围、size 容器尺寸、ref 跨表引用、path 路径、nonneg 非负…）。实现：`RawField.handles: Vec<Handle{name, arg}>`，compile_record 时桥接到 `type_info.tags`（现有校验器注册表零改动复用）；compile_bean 遇句柄直接报错——Bean 是纯结构类型，数据校验职责在数据表层。

## 5. 数据格式决策（git 友好）

- **源数据 = 自定义文本格式**（`#version:0.1` 简化 jsonl，一行一记录、字段顺序由 schema 决定、字段名只在表头出现一次）
- **JSON = 便捷导入 / 工具互操作格式**（双向转换，接"Luban 兼容导入"路线）
- git 友好手段：map 表按索引稳定排序、list 表保留人工顺序、保存不重排文件、`one` 单对象

## 6. 百万级数据 + 流畅 UI

- 前端**虚拟滚动**（只渲染可视窗口 ± buffer，`react-window`/`@tanstack/react-virtual`）
- 后端**分页窗口** `get_rows(table, offset, limit)`，绝不整表 JSON 到前端
- 单元格**单点更新** `update_cell(...)`，前端只重渲染那一格
- map 表 HashMap 索引 O(1)；list 表 Vec + BTree 二级索引
- 分级：<10 万行整表内存 + 虚拟滚动；>10 万行后端分页窗口

## 7. 公式系统（不存公式进数据表）

**核心：区分"事实"与"派生"。**

- **computed 列（活公式）**：独立文件 `schemas/computed/<Table>.computed.json`，定义 `{field, type, expr}`；源数据只存基础字段，**导出时才物化**。新增公式 = 改一个文件一行，全表自动生效，零数据行变更。
- **单元格覆盖（稀疏特例）**：`datas/overrides/<Table>.overrides.json`，`{rowKey, field, expr}`。
- **固化批量填充**：`apply_formula(table, field, expr, filter?)` → 预览前 N 行 → 确认 → 写回落盘（可 git 回滚）。

公式引擎要求：静态类型检查、沙箱纯函数、依赖图 + 环检测 + 拓扑求值。

## 8. 跨表引用（外键）

类型语法 `ref<TbX>` / `fk<TbX.id>`；`ForeignKeyValidator` 在数据加载后校验引用存在性；**两阶段数据校验**（先建所有表索引，再跨表校验）。

## 9. P1 实现范围与测试

P1 交付：`diagnostic` / `types`（类型系统+解析器）/ `defs`（Raw+Def 层+单定义编译）/ `symbol`（符号表+依赖图+增量编译）。

**测试目标（增量编译机制的可测试化）**：
1. 创建即校验：register 引用不存在类型的 Bean → 立即"未解析类型"诊断
2. 增量重检：修改被引用的 Enum → 只有引用它的定义被重检（`last_rechecked` 断言），无关定义不动
3. 删除传播：remove 被引用的 Enum → 引用者立即变错误
4. 恢复：重新 register 该 Enum → 引用者错误消失
5. `validate_draft` 不污染符号表（计数/诊断不变）
6. 全量编译：`compile_all` 正确计数 + 诊断
7. 类型串解析：基础/容器/嵌套/可空/标签/别名
8. 继承：字段 shadow 冲突、继承环检测
9. 表索引：`a+b` 联合 / `a,b` 多键 / 索引列不存在诊断

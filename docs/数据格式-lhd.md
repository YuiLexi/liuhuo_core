# LiuHuo 内置数据格式 `.lhd`（LiuHuo Data）设计

> 状态：设计稿 v1（待实现）。`.lhd` 是 LiuHuo 的**内置默认数据格式**；JSON / XML / Excel / CSV 作为后续 `IDataLoader` 扩展格式。

---

## 0. 行优先 vs 列优先 —— 结论先行

用户直觉"列优先更有优势（数据校验和增删改查）"**对了一半**：那些优势是**运行时表示**的优势，不是**文件格式**的优势。两者必须拆开决策：

| 维度 | 行优先文件（一行一记录） | 列优先文件（一列一块） |
|---|---|---|
| git diff | **一行变更 = 一条记录变更**，语义对齐 | 增 1 条记录 = **每一列块都改**，diff 碎片化 |
| git merge | 按主键三方合并可行（行 = 天然对齐单元） | 冲突无法自动定位到记录 |
| 追加写入 | **尾部加一行，O(1)** | 所有列块重排 |
| 人类可读 | 直接读 | 需要工具拼装 |
| 校验/查询/CRUD 性能 | —— 与文件无关，取决于加载后的内存表示 —— | —— |

**结论：文件层行优先（git/协作/可读性全胜），运行时层列式/索引（校验与增删改查性能由加载器负责）。**

`.lhd` 加载后由 loader 构建：

1. `Vec<Record>` 行数组（编辑保序）
2. 主键 → 行号 `HashMap`（map 表 O(1) 点查）
3. 列缓存（后续换 Arrow RecordBatch，DuckDB 查询、rayon 并行校验，见架构文档 P2）

百万级不是文件格式问题，是分片 + 并行加载问题（§6）。

## 1. 设计目标（对齐需求清单）

| 需求 | 对应机制 |
|---|---|
| git 友好 | 一行一记录；保存时按主键稳定排序；确定性序列化（§5） |
| 百万数据 | 分片文件 + 分片并行解析 + 主键分片定位（§6） |
| 增删改查性能 | 运行时 PK 索引 + 行式数组；文件层单行局部性（§0/§5） |
| 无冗余 | 字段名只在头部出现**一次**（schema-first，行内零字段名） |
| 注释 | `//` 整行注释 + 行尾注释（§3.4） |
| 元数据 | `##` 头部指令块（§3.1） |
| 数据标签 | 行尾 `@tag(...)`，配合导出 tag_filter（§3.3） |
| 多数据类型 | 类型指导解析，覆盖全部 TypeKind（§4） |

## 2. 语法总览

```text
┌─────────────────────────────────────────────────────────────┐
│ .lhd 文件 = 头部指令块 + 数据行块                              │
│                                                             │
│   ## key=value          头部元数据指令（机器读）               │
│   // 注释               注释（人读，可出现在任何位置）          │
│                                                         │
│   值1|值2|值3|...       数据行：字段顺序 = ## fields 声明顺序  │
│                         行尾可附 @tag(...) 与 // 注释          │
└─────────────────────────────────────────────────────────────┘
```

完整示例（`datas/TbEquip.lhd`）：

```
// ─── 装备表 ───
// 字段定义见 schemas/beans/EquipCfg.json，改字段请先改 schema
## format=lhd
## version=1
## table=TbEquip
## record=game.EquipCfg
## fields=id|name|quality|atk|price|tags|attr
## order=id
## schema=8f3a91c2

// 品质枚举: White=0 Green=1 Blue=2 Purple=3
1|"铁剑"|Green|10|100|["武器","金属"]|{锐利=5,重量=3}
2|"寒冰弓"|Blue|22|800|["武器","冰霜"]|{冰伤=12} @tag(dev)
3|"紫金冠"|Purple|0|4200|()|{}        // 头饰，无属性
4|"旧木盾"|White|3|50|["防具"]|{耐久=8} @tag(test,deprecated)
```

## 3. 语法细则

### 3.1 头部指令块（`##`）

| 指令 | 必填 | 说明 |
|---|---|---|
| `## format=lhd` | ✅ | 格式标识，loader 据此分发 |
| `## version=1` | ✅ | **格式语法版本**（不是数据版本），后续语法演进用 |
| `## table=TbEquip` | ✅ | 表名，与 schema 的 DefTable 对应 |
| `## record=game.EquipCfg` | ✅ | 值类型 full_name（即用户草稿的 `record_type`） |
| `## fields=a\|b\|c` | ✅ | 字段名**一行清单**——文件的自描述底线：①加载时与 schema 层级字段逐一核对（数量/名称/顺序），schema 变更能被立即发现而不是静默错位；②外部 diff 工具无需理解 schema 也能对齐列 |
| `## order=id` | ✅ | 排序键（map 表=主键；list 表=`-` 表示保留人工顺序不重排） |
| `## schema=8f3a91c2` | ➖ | schema 指纹（record 类型名+字段名+字段类型串的 FNV-1a 哈希）。不匹配时**警告不阻断**，提示"schema 已变更，请核对字段映射"——挡住字段增删导致的静默错位，又不强制同步改数据 |
| `## @key value` | ➖ | 自定义元数据（如 `## @author lyra`、`## @reviewed`），loader 透传不解释 |

规则：头部必须出现在任何数据行之前；指令顺序不限；`##` 行不缩进。

### 3.2 数据行

```text
值1|值2|值3|…[@tag(…)][// 注释]
```

- 顶层分隔符 `|`；括号/引号内（深度 > 0 或字符串态）的 `|` 不分割
- **空字段 = 默认值**（schema 的 default）；显式 `null` = 可空字段的空值（写入非可空字段报诊断）
- 一个 `|` 都没有的空行直接跳过；纯注释行（`//` 开头）跳过
- 一行 = 一条记录，**字符串内换行必须转义 `\n`**，保证"一行一记录"物理成立（git diff/blame 的前提）

### 3.3 行标签 `@tag(...)`

- 语法：行尾（注释之前）`@tag(dev)` 或多标签 `@tag(dev,release)`；键值标签 `@tag(stage=alpha)`
- 语义：导出时配合 `liuhuo.config.yaml` 的 `tag_filter`（include/exclude）过滤数据行
- 被 `deprecated` 类标签标记的行在 GUI 中灰显（提示而非删除）

### 3.4 注释

- `//` 整行注释：任何位置，独占一行
- `//` 行尾注释：数据行尾部（`@tag` 之后），要求前面至少一个空白；解析器在**引号态之外**剥离注释——字符串里的 `//` 不受影响
- 注释是**文件的一部分**，参与 diff；保存时保留原注释行（loader 记录注释的行位置，未紧邻数据行变更的注释原样写回）

### 3.5 注释行占位（删除标记）

被删除的数据行保留为注释（迁移期防手滑），如：

```
// 5|"魔杖"|Blue|30|600|["武器"]|{} @tag(removed@2026-09-02)
```

不参与加载，git 历史仍可追。

## 4. 值语法（类型指导解析）

解析器拿着 schema 的 `TypeInfo` 走，**语法歧义由类型消解**。对照表（采纳用户草稿的分隔符体系，做了一处调整，见备注）：

| 类型 | 语法 | 示例 |
|---|---|---|
| bool | `true` / `false` | `true` |
| 整数 i8..u64 | 十进制 / `0x` / `0b` / `_` 分隔 / 负号 | `100`、`0xFF`、`1_0000` |
| 浮点 f32/f64 | 十进制小数/科学计数 | `3.1415`、`1e-3` |
| 字符串 string | `"..."`（转义 `\"` `\\` `\n` `\t` `\u{XXXX}`） | `"小明"` |
| 文本 text | 同 string（l10n 提取器按类型区分） | `"你好"` |
| 时间 datetime | Unix 秒（i64） | `1790000000` |
| 枚举 enum | **裸名字**/别名/数值 | `Green`、`W`、`1` |
| 列表/数组 | `[v, v, v]` | `[1, 2, 3, 4]` |
| 集合 set | `(v, v, v)` | `("a", "b", "c")` |
| **字典 map** | `{k=v, k=v}` | `{锐利=5, 重量=3}` |
| 结构 bean | `{v \| v \| v}`（按层级字段顺序） | `{1 \| "小红" \| female}` |
| 可空 | `null` 或空 | `null` |
| 跨表引用 ref | 同整数（目标表主键值） | `1003` |

> **对用户草稿的一处调整**：草稿中字典写作 `[say="hello"]`，与列表 `[...]` 同括号。改为**花括号 + 等号** `{say="hello", alias="明明"}`：
> - `{...=...}` 与 `[...]`（列表）、`(...)`（集合）三种括号一眼可辨；
> - 字典与结构同为"花括号家族"（都是键值/字段语义），内部符号区分：字典 `=`，结构 `|`；
> - 类型指导解析下两者本无歧义，此调整纯粹提升**人读与 diff 审读**体验。
> 其余分隔符（列表 `[]`、集合 `()`、结构 `{}|`、行分隔 `|`）与草稿一致。

嵌套示例（map 的值是 bean，bean 里又有 list）：

```
7|"魔典"|Purple|15|900|["武器","法器"]|{强化={1|"火球"|[5,10]}, 诅咒=null}
```

### 4.1 多态 bean 行

值类型是继承体系父类时，行首以 `@type(子类名)` 声明实际类型：

```
@type(WeaponCfg)|1|"铁剑"|Green|10|100
@type(ArmorCfg)|2|"板甲"|White|0|300
```

`@type` 字段不占 `## fields` 位；无标记时默认 = value_type 本身（非多态表禁止使用，报诊断）。

## 5. 保存约定（git 友好的确定性）

保存（导出回 `.lhd`）时 loader 必须保证**幂等**——同样的数据两次保存产生字节级相同的文件：

1. **主键稳定排序**：`## order` 键排序（数值键按数值序，字符串键按字典序）；list 表（`order=-`）保留人工顺序永不重排
2. **确定性序列化**：字段顺序 = schema 层级字段顺序；浮点用 Rust 最短往返表示；字符串转义规则固定；行尾 LF、UTF-8 无 BOM
3. **最小扰动写回**：GUI 编辑只重写受影响分片（§6），未动分片文件 mtime 不变
4. 头部 `## fields` / `## schema` 每次保存按当前 schema 重算刷新

效果：改一个单元格 = git diff 一行；加一条记录 = diff 一行；两人各改不同行 = 自动合并。

## 6. 大表分片（百万级）

单文件超过阈值（默认 5 万行）建议分片：**同目录、同名前缀、点分序号**：

```
datas/TbMonster.lhd            # 头部 + 首片（或仅头部做目录页）
datas/TbMonster.0001.lhd
datas/TbMonster.0002.lhd
...
```

- 每片**独立完整头部**（同 `## fields`/`## schema`，`## shard=0001`）；单片可独立校验
- 分片按主键**范围划分**（0001 = id 1–10000）：点查先二分定位分片再片内索引；并行加载/校验天然按片分工（rayon）
- 追加写 = 只动最后一片；改一行 = 只动一片 → **git diff 永远局部化**
- 分片是建议不是强制：`.lhd` 单文件合法，小表永远单文件

## 7. 加载管线与诊断

```
.lhd 文件 → 头部解析 → 与 schema 核对（fields 一致性 + schema 指纹）
         → 逐行类型指导解析（引号态感知的顶层分割）
         → TableData + PK 索引 + 注释/标签保留
```

- **错误收集不快速失败**：逐行收集诊断（对齐 loader `(records, diagnostics)` 约定），错误定位 `表名.lhd[行N].字段名`；JSON loader 的文件级 fail-fast 是它自己的历史行为，`.lhd` 作为默认格式必须做到逐行
- 头部 `fields` 与 schema 不一致 → **Error**（数量/名称错位风险）；仅 `schema` 指纹不匹配 → Warning
- 编码/换行：UTF-8、LF；CRLF 容忍读入、统一 LF 写出

## 8. 与扩展格式的关系

`.lhd` 是唯一**内置默认**（`TextDataLoader` 演进为 `LhdDataLoader`，扩展名 `.lhd`；旧 `.txt` 格式保留只读兼容一个版本）。JSON / XML / Excel / CSV 全部走 `IDataLoader` trait 注册表按扩展名接入，**加载后与 `.lhd` 同构**（同一 TableData + 索引），导出侧同理 `IExporter`。GUI 内部编辑永远走 `.lhd`，外部格式定位为"导入源/交付物"。
